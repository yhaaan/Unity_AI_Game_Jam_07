# 동물 파츠 ScriptableObject 구현 계획

기준: [게임 기획서](GameDesignDocument.md) §3~6. 아래 파츠 값은 현재 기획 기준이며, 타입명·시트 형식·가져오기 방식은 구현 제안이다.

## 1. 무엇을 에셋으로 만들 것인가

`AnimalPartDefinition` 한 타입으로 **동물 5종 × 슬롯 3개 = 15개 에셋**을 만든다. 파츠는 바뀌지 않는 정의이고, 캐릭터 조합은 이 에셋 세 개를 참조하는 런타임 값이다. 가능한 125개 조합을 에셋으로 만들지 않는다.

| 데이터 | 작성 위치 | 소비자 |
| --- | --- | --- |
| `partId`(고정 키), `animal`, `slot`, `displayName`, `description`(장점·약점) | Google Sheets의 `Parts` 탭 | 에디터 임포터, 추첨 카탈로그, 조립 결과 UI |
| `speedDelta`, `jumpDelta`, `weightDelta`, `healthDelta`(부호 있는 정수), `effectIds`(등록된 효과 ID 목록) | 같은 행 | 스탯 계산기, 이동·환경 판정 코드 |
| 스프라이트 등 외형 참조 | Unity의 해당 파츠 에셋 | 캐릭터 외형 조립. 장식은 관련 파츠 외형에 포함 |
| 선택한 세 파츠, 최종 스탯, 현재 체력·효과 타이머 | 플레이 중 캐릭터/스테이지 상태 | 이동, 재시작, 결과 UI. 공유 SO에 쓰지 않음 |

## 2. 최초 15개 에셋 명세

`partId`는 표시명·행 번호와 독립적이다. 표의 숫자는 최종 단계가 아닌 **기본값 3에 더할 보정**이다. 효과가 없으면 빈 목록으로 저장한다. 동물과 슬롯은 시트에 별도 열로 기록한다.

| partId | 속도 | 점프 | 무게 | 체력 | 효과 ID / 적용 의미 |
| --- | ---: | ---: | ---: | ---: | --- |
| chicken_head | 0 | 0 | -1 | 0 | `SideDrift`: 이동 중 주기적 좌우 쏠림 |
| chicken_body | 0 | 0 | 0 | -1 | `Glide`: 활강 |
| chicken_legs | +1 | +1 | -1 | 0 | `ShortStature`: 콜라이더 높이 감소 |
| monkey_head | 0 | 0 | 0 | 0 | `BananaFrenzy`: 바나나 발견 시 광분 |
| monkey_body | 0 | 0 | 0 | +1 | `WallClimb`: 벽타기 |
| monkey_legs | 0 | 0 | 0 | 0 | 없음. 균등 추첨에 포함 |
| lion_head | 0 | 0 | +1 | 0 | `PredatorSafe`: 포식자에게 안전 |
| lion_body | 0 | 0 | 0 | +2 | 없음 |
| lion_legs | +1 | 0 | 0 | 0 | 없음 |
| kangaroo_head | 0 | 0 | 0 | 0 | `HunterVulnerable`: 사냥꾼에게 불리 |
| kangaroo_body | 0 | 0 | 0 | +2 | 없음 |
| kangaroo_legs | 0 | +1 | 0 | 0 | 없음 |
| duck_head | 0 | 0 | 0 | 0 | `HunterVulnerable`: 사냥꾼에게 불리 |
| duck_body | 0 | 0 | 0 | 0 | `Float`: 물에서 실패하는 대신 수면 경로 이용 |
| duck_legs | 0 | -1 | 0 | 0 | 없음 |

## 3. 조립 및 적용 순서

1. `PartCatalog`가 슬롯별 목록을 제공한다. 스테이지 입장 또는 명시적 재소환 시 각 목록에서 균등하게 하나씩 독립 추첨한다. 같은 동물 중복 허용, 세트 보정 없음. 실패로 시작 지점에 돌아갈 때는 재추첨하지 않는다.
2. 각 스탯을 `Clamp(3 + 머리 보정 + 몸통 보정 + 다리 보정, 1, 5)`로 계산한다. 그 뒤 최종 무게가 4 이상이면 이동속도만 1 감소시킨다(최소 1). 무게로 점프나 낙하 속도를 바꾸지 않는다.
3. 단계별 튜닝 표로 속도·점프 단계를 실제 수치로 바꿔 기존 `PlayerMotor2D.MoveSpeed`와 `JumpVelocity`에 전달한다. 실제 수치표는 별도 결정한다. UI는 이동 코드와 같은 조립 결과를 읽는다.
4. 이동 코드는 활강·벽타기·쏠림 효과를 기존 입력과 상황 판정에 통합한다. 물·적 등 환경 객체는 효과와 **머리의 동물 정체성**을 조회한다. 효과를 파츠 ID나 표시명으로 분기하지 않는다. 재소환 시 이전 효과와 콜라이더 변경을 해제한 뒤 새 조합을 적용한다.

## 4. Google Sheets 연동

`Parts` 탭을 **파일 → 공유 → 웹에 게시**로 게시한다. Unity의 **Tools → RTD → Animal Parts Importer**에 해당 탭의 `pub` 또는 `pubhtml` 링크를 붙이고 **게시 시트 가져오기**를 누른다. 일반 편집/공유 링크가 아닌 공개 게시 데이터만 지원한다. 여러 탭이 있는 경우 `gid`가 포함된 Parts 탭 링크를 사용한다. 게시하면 외부에서 읽을 수 있으므로 비공개 데이터는 포함하지 않는다.

[PartsTemplate.txt](PartsTemplate.txt)는 기획값 15행이 들어 있는 UTF-8 CSV다. `.csv`로 복사해 Google Sheets에 가져오거나, 에디터의 **로컬 CSV 가져오기**에서 원본 `.txt`를 선택해 네트워크 없이 초기 에셋을 생성할 수 있다. 새 파츠 및 `PartCatalog.asset`은 `Assets/06. Data/`에 생성된다. `partId`에는 영문·숫자·`_`·`-`만 사용한다. 빌드에서는 로컬 에셋만 읽는다.

```csv
partId,animal,slot,displayName,description,speedDelta,jumpDelta,weightDelta,healthDelta,effectIds
chicken_body,Chicken,Body,닭 몸통,활강 가능 / 체력 감소,0,0,0,-1,Glide
```

- 슬롯 값은 `Head`, `Body`, `Legs`. 효과가 여러 개면 `|`로 구분하고 없으면 빈 셀을 쓴다. CSV의 따옴표·쉼표를 처리하는 파서를 사용한다.
- **쓰기 전 전체 검증**: 필수 열, 정수 보정값, 등록되지 않은 동물·슬롯·효과, 빈 키/중복 키, 동물×슬롯 조합의 중복·누락을 검사한다. 오류는 행·열과 함께 표시하고 아무 에셋도 변경하지 않는다.
- 검증 후 `partId`로 기존 에셋을 찾아 시트 소유 필드만 제자리 갱신한다. 새 ID만 생성하며 기존 GUID와 외형 참조를 보존한다. 기존 ID가 입력에서 사라지면 자동 삭제하거나 새 ID로 대체하지 말고 확인 대상으로 보고한다.

## 5. 구현 순서와 완료 기준

| 순서 | 작업 | 완료 기준 |
| --- | --- | --- |
| 1 | 공통 SO, 슬롯·동물·효과 타입, 카탈로그 정의 | 한 타입으로 중립 파츠와 복합 효과를 표현할 수 있다. |
| 2 | CSV 임포터 구현, 위 표로 에셋 15개 생성 | 재가져오기 시 중복 생성 없이 외형 참조 유지. 잘못된 효과 ID 한 칸을 넣은 입력은 전체 거부한다. |
| 3 | 조립·스탯 계산 및 EditMode 테스트 | 슬롯당 후보 5개. 125개 조합의 단계 범위를 검증한다. 사자 머리+사자 몸통+사자 다리는 속도 3·점프 3·무게 4·체력 5가 된다(세트 효과 없음). |
| 4 | 플레이어·환경·UI 연결 및 플레이 확인 | 조립 결과 표시와 이동이 일치한다. 실패 시 조합 유지, 재소환 시 이전 효과 제거, 오리 몸통 유무에 따른 물 판정을 확인한다. |

**후속 기획 결정:** 재소환 횟수·비용, 단계별 실제 이동/점프 수치, 체력 사용처, 활강·벽타기 입력 조건, 광분 및 적 반응 세부 동작. 해당 값이나 동작을 확정하지 않아도 SO 정의와 시트 검증부터 구현할 수 있다.
