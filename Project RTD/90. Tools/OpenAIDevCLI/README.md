# Unity Game Jam

OpenAI Responses API 크레딧으로 Unity 프로젝트의 코드 작업을 수행하는 로컬 브라우저 채팅이다.
Codex 사용량 대신 API Platform 크레딧을 사용하며, 실행 중인 Unity Editor에는 Unity CLI로 연결한다.

## 실행

PowerShell에서:

```powershell
& '.\Project RTD\90. Tools\OpenAIDevCLI\start.ps1'
```

또는 루트의 `Start-Unity-Game-Jam.cmd`를 더블클릭한다. 로컬 서버 창과 기본 브라우저가 열린다.

브라우저 상단의 `+ 세션`으로 독립된 API 대화를 추가할 수 있다. 각 세션은 대화 문맥, 모델, 토큰 누계를 따로 유지하며, 세션 이름은 첫 요청으로 자동 생성된다. `×`를 누르면 해당 세션의 대화 문맥이 제거된다. 다른 세션의 API 요청은 동시에 진행할 수 있고, 파일 변경·Unity 컴파일·테스트 도구만 충돌 방지를 위해 순서대로 실행된다.

기존 터미널 UI가 필요하면 다음처럼 실행한다.

```powershell
& '.\Project RTD\90. Tools\OpenAIDevCLI\start.ps1' --cli
```

프롬프트 예시:

```text
현재 플레이어 이동 코드를 분석하고 점프 버그를 수정한 뒤 컴파일해줘.
Stage01 씬에서 Player 오브젝트의 컴포넌트와 이동 속도 값을 확인해줘.
지금 선택한 오브젝트가 어떤 스크립트로 움직이는지 설명해줘.
앞으로 적 AI는 PlatformEnemy 하나로 통합한다. 기억해줘.
```

## 자동으로 하는 일

- **프로젝트 인덱스**: 시작 시 텍스트 파일을 인덱싱하고 20초마다, 그리고 요청마다 다시 스캔한다. 지난 요청 이후 Unity·IDE·다른 세션에서 바뀐 파일을 다음 요청에 알려준다.
- **프로젝트 이해**: `AGENTS.md`, README, `Packages/manifest.json`, asmdef 참조 관계, Unity 버전, 입력 시스템, 빌드 씬 순서, 태그·레이어·소팅 레이어, `99. Documents` 문서 목록을 요약해 지시문에 넣는다. 이 파일들이 바뀔 때만 다시 만든다.
- **Unity 실시간 조회(읽기 전용)**: 열린 씬과 Editor 상태, Hierarchy 트리와 컴포넌트, GameObject 검색, 인스펙터 필드 값, 현재 선택 오브젝트를 조회한다. Editor가 이 프로젝트로 열려 있어야 한다.
- **세션 복원**: 세션, 대화 기록, 토큰 누계는 저장소 루트의 `.unity-game-jam-state.json`에 저장되어 서버를 다시 켜도 이어진다.
- **장기 기억**: 사용자가 정한 규칙·설계 결정과 작업 요약을 `.unity-game-jam-memory.json`에 저장하고 모든 세션의 지시문에 넣는다. 파일을 바꾼 작업은 자동으로 한 줄 요약이 남는다. 상단 `프로젝트·기억`에서 보고, 추가하고, 삭제할 수 있다. 두 파일 모두 Git에서 제외된다.
- **관련 파일 선별**: 요청 문장의 영어 식별자와 자주 쓰는 한국어 단어(플레이어, 점프, 적 등)로 C# 파일 이름·클래스·메서드를 점수화해 후보 8개를 알려준다. 모델은 후보 중 필요한 파일만 읽는다.
- **컴퓨터 전체 접근**: 기본 접근 범위는 `컴퓨터 전체`다. 절대 경로(`C:/...`)나 `~`로 프로젝트 밖의 텍스트 파일도 읽고 쓴다. 상단 `접근 범위`에서 `프로젝트만`, `Assets만 쓰기`로 줄일 수 있다(`/scope full|project|assets`, 환경 변수 `OPENAI_DEV_WRITE_SCOPE`). 바꾼 파일은 모두 백업되어 `/undo`로 되돌릴 수 있다.
- **비밀정보 차단(모든 범위)**: `.env*`, `.ssh`·`.aws` 등 자격증명 폴더, 키·인증서 파일, 이름에 token/credential/secret/password가 든 설정 파일, 브라우저 프로필, Windows 자격증명, Unity Hub와 `unity-ai` 설정(지출 한도 포함), 이 도구의 상태·기억 파일은 읽지도 쓰지도 않는다. 이 도구 자신의 코드도 수정하지 못한다.
- **삭제**: 에이전트가 `delete_path`로 파일·폴더를 지울 수 있다. 지우기 전에 백업하고, `Assets` 안의 에셋은 `.meta`도 함께 지운다. 드라이브 루트, 홈·바탕화면·문서·다운로드·AppData, Windows·Program Files, 저장소·프로젝트·`Assets`·`ProjectSettings`·`Packages` 폴더 자체와 항목 20,000개가 넘는 폴더는 지울 수 없다.
- **되돌리기**: `프로젝트·기억`의 `에이전트 변경 모두 되돌리기`(CLI는 `/undo`)로 이번 서버 실행에서 에이전트가 수정·생성·삭제한 것을 시작 전 상태로 되돌린다. 백업은 서버를 끄면 사라진다.
- **도구 호출 제한 없음**: 한 요청 안의 도구 호출 횟수에 상한이 없다. 작업 중에는 `전송` 버튼이 `중단`으로 바뀌며, 누르면 실행 중인 도구가 끝난 뒤 멈춘다. 중단·오류·서버 재시작 뒤에도 진행 상황이 저장되어 다음 요청에서 이어진다. 상한이 필요하면 `OPENAI_DEV_MAX_TOOL_ROUNDS`로 정한다.
- **Git 커밋**: 요청하면 에이전트가 `git_commit`으로 지정한 파일만 커밋한다. 다른 스테이징 파일은 섞이지 않는다. `git_log`로 기존 메시지 형식을 따른다. 푸시·amend는 하지 않는다.
- **Unity AI 크레딧**: Unity 계정 크레딧으로 스프라이트·텍스처·사운드·음악·3D 모델·스카이박스 등을 생성한다. 모델 목록·파라미터·견적은 무료이고, 생성은 `unity ai consent set`으로 직접 정한 1회·하루 한도 안에서만 실행된다. 에이전트는 한도를 바꾸거나 넘길 수 없다. 하단에 크레딧 잔액과 오늘 남은 한도가 표시된다.
- **토큰 절약**: 지시문 앞부분을 요청마다 동일하게 유지하고 세션별 `prompt_cache_key`를 보내 프롬프트 캐시를 최대한 재사용한다.

## 모델·토큰 표시

- 상단에서 **모델 계열**(Astra/Sol/Luna 등)과 **버전**(6.2, 6.1, 6 등)을 따로 고른다. 목록은 API 키로 조회 가능한 모델(`/v1/models`)과 기본 목록(`gpt-6.2-astra`, `gpt-6.2-sol`, `gpt-6.1-sol`, `gpt-6-luna`)을 합친 것이다.
- **추론 강도**(low/medium/high)는 세션마다 저장되며 문맥을 초기화하지 않는다. 모델을 바꾸면 그 세션의 대화 문맥은 초기화되고 기록은 남는다.
- 하단에 현재 컨텍스트 사용량과 남은 토큰(게이지), 세션 누적 입력·캐시·출력·추론 토큰, 오늘 전체 사용량이 표시된다. 답변마다 그 요청의 토큰 사용량이 붙는다.
- 컨텍스트 창 크기는 기본 1,050,000 토큰으로 계산하며 `OPENAI_DEV_CONTEXT_TOKENS` 환경 변수로 바꿀 수 있다.
- 남은 크레딧 잔액은 API 키로 조회할 수 없으므로 OpenAI Platform의 Usage 화면에서 확인한다.

## CLI 명령

- `/model`: 현재 모델과 선택 가능한 모델 목록을 표시한다.
- `/model <id|astra|sol|luna>`: 모델을 바꾼다. 예: `/model gpt-6.1-sol`
- `/effort low|medium|high`: 추론 강도를 변경한다.
- `/scope full|project|assets`: 파일 접근 범위를 컴퓨터 전체, 프로젝트, `Assets` 쓰기로 바꾼다. 기본값은 full이다.
- `/new`: API 대화 문맥을 초기화한다.
- `/status`: 토큰 사용량, 남은 컨텍스트, 이번 세션 변경 파일을 표시한다.
- `/memory`: 장기 기억을 표시한다.
- `/undo`: 이번 실행에서 CLI가 변경한 모든 파일을 시작 전 상태로 복원한다.
- `/exit`: 종료한다.

도구 계층만 점검할 때는 API 없이 읽기 전용 도구 하나를 실행할 수 있다.

```powershell
node '.\Project RTD\90. Tools\OpenAIDevCLI\api-dev.mjs' --tool unity_hierarchy '{\"max_depth\":2}'
```

## 안전 범위

- `.env.local`의 `OPENAI_API_KEY`는 메모리에서만 읽고 출력하지 않는다.
- `Library`, `Temp`, `Logs`, 비밀정보 파일은 모델에 전달하지 않는다.
- 자동 쓰기는 접근 범위 안의 허용된 텍스트 파일을 대상으로 한다. Unity AI 생성 결과만 바이너리로 저장된다.
- 기존 파일은 먼저 읽은 뒤 정확한 텍스트 교체로만 수정한다.
- `Packages`, `ProjectSettings`, `.vscode`, `90. Tools`도 수정할 수 있다.
- `.git`, `Library`, `Temp`, `Logs`, 빌드 산출물, 비밀정보와 바이너리 파일은 계속 차단한다.
- 에이전트가 `OpenAIDevCLI` 자신의 실행 코드와 권한 규칙을 수정하는 것은 차단한다.
- 푸시, 패키지 설치, 빌드, Unity Editor 종료 기능은 제공하지 않는다. 커밋은 요청할 때만 지정 파일 단위로 하고, 삭제는 백업 후에만 한다.
- Unity 작업은 상태·씬 조회(읽기 전용), 재컴파일, EditMode 테스트로 제한한다. 씬 오브젝트를 바꾸는 명령은 제공하지 않는다.
- 장기 기억에는 비밀 키로 보이는 내용을 저장하지 않는다.

API 사용량은 OpenAI Platform의 Usage 화면에서 최종 확인한다.
